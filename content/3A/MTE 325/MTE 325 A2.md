## Question 1
For each of the following data transfer scenarios, calculate the total wall clock time required by a CPU to read 1000 bytes of data from a device. Assume that the bus can only transfer one byte at a time.

![[MTE 325 A2.png]]

### Spontaneous Data Generation
If the data produces data spontaneously, the transfer of data will overlap with the production of data  
for the next transfer. In this scenario, the total time may be calculated as follows:
$$
\text{Total time} = \text{Time to produce 1000 bytes of data} + \text{Transfer time for final transfer} + \text{Latency}
$$
For each of the scenarios:

**Scenario 1:**
$$
\text{Scenario 1:}  \quad 10 \text{ ms} \times 1000 + \max(2 \text{ ms}, 4 \text{ ms}) \times 1+0 \text{ ms} \times 1 = 10.004\text{ s}  \\[2ex]
$$
- Data production: Each byte of data is produced in 10 ms, this happens 1000 times.
- Transfer time: Because the data is spontaneous, we don't wait for the previous piece of data to finish transferring, which means that the data transfer time is completely covered by the production time, except for the transfer of the last byte. Thus, we only need to take the transfer time for the final transfer. Device transfer time is data transferring from the device to the CPU, and CPU transfer time is the time it takes for the CPU to consume the data. These are parallel processes that happen concurrently, so we take $\max(2 \text{ ms}, 4 \text{ ms})$. 
- No latency.

**Scenario 2:**
$$
\text{Scenario 2:}  \quad 10 \text{ ms} \times \frac{1000}{2} + \max(4 \text{ ms}, 2 \text{ ms}) \times 2+0 \text{ ms} \times 1 = 5.008 \text{ s} \\[2ex] 
$$
- Data production: Data is produced in blocks of 2, so we multiply by 500 instead.
- Transfer time: We only need the final transfer time, take the max because Device Transfer and CPU Transfer are parallel processes. However, we have to multiply by 2; even though we produce 2 bits at a time, the data has to be one byte at a time.
- No latency.

**Scenario 3:**
$$
\text{Scenario 3:}   \quad 20 \text{ ms} \times 1000 + \max(2 \text{ ms}, 4 \text{ ms})\times 1+3 \text{ ms} \times 1 = 20.007\\[2ex] 
$$
- Data production: Data is produced in blocks of 1, so we multiply by 1000.
- Transfer time: We once again take the max because Device Transfer and CPU Transfer the data is generated spontaneously. 
- Latency due to interrupts.

**Scenario 4:**
$$
\text{Scenario 4:}  \quad 20 \text{ ms} \times \frac{1000}{2} + \max(2 \text{ ms}, 4 \text{ ms})\times 2+0 \text{ ms} \times 1 = 10.011
$$
- Data production: Data is produced in blocks of 2, so we multiply by 1000.
- Transfer time: We once again take the max because Device Transfer and CPU Transfer. This needs to be done twice.

### Consumer Sensitive Data Generation
If the device produces data using a consumer sensitive approach, then the total time will include the  
time to produce the data, the transfer time, and the latency associated with synchronization. Here, the transfer of data does not overlap with the production of data, so both have to be done separately.
$$
\text{Total time} = \text{Time to produce 1000 bytes of data} + \text{Transfer time for each transfer} + \text{Latency}
$$
- For polling synchronization, the latency is quite short as the device is serviced as soon as a poll indicates service is needed. 
- For interrupt synchronization, a noticeable latency can occur as the CPU will need to complete its current instruction, save some or all of its internal registers, and then start the interrupt service routine. In this scenario, the total time may be calculated as follows:

Scenario 1:
$$
\text{Scenario 1:}   \quad 10 \text{ ms} \times 1000 + \max(2 \text{ ms}, 4 \text{ ms}) \times 1000+0 \text{ ms} \times 1000 = 14\text{ s}  \\[2ex]
$$
- Data production time: 10 ms for each byte, multiplied by 1000
- Transfer time: We need to wait for the consumer to be done with the previous piece of data, so we also need to multiply by 1000.
- No latency.

Scenario 2:
$$
\text{Scenario 2:}   \quad 10 \text{ ms} \times \frac{1000}{2} + \max(4 \text{ ms}, 2 \text{ ms}) \times 1000+0 \text{ ms} \times \frac{1000}{2} = 9 \text{ s}
$$
- Data production time: 10 ms for 2 bytes, so multiplied by 1000/2
- Transfer time: We need to wait for the consumer to be done with the previous piece of data, so we also need to multiply by 1000.
- Even though we need 1000 transfers because the bus can only transfer 1 byte at a time, we only need 500 requests from the consumer. 

Scenario 3:
$$
\text{Scenario 3:}   \quad 20 \text{ ms} \times 1000 + \max(2 \text{ ms}, 4 \text{ ms})\times 1000+3 \text{ ms} \times 1000 = 27 \text{ s}\\[2ex] 
$$
- Data production time: 20 ms for 1 byte, multiplied by 1000
- Transfer time: We need to wait for the consumer to be done with the previous piece of data, so we also need to multiply by 1000.
- Each of the 1000 transfers is triggered by an interrupt with 3 ms latency.

Scenario 4:
$$
\text{Scenario 4:}   \quad 20 \text{ ms} \times \frac{1000}{2} + \max(2 \text{ ms}, 4 \text{ ms})\times 1000+3 \text{ ms} \times \frac{1000}{2} = 15.5 \text{ s}
$$
- Data production time: 20 ms for 2 bytes, so multiplied by 1000/2
- Transfer time: We need to wait for the consumer to be done with the previous piece of data, so we also need to multiply by 1000.
- Even though we need 1000 transfers because the bus can only transfer 1 byte at a time, we only need 500 requests from the consumer. Each of these requests have 3 ms of interrupt latency.

Note that a consumer responsive approach is not possible given the information provided. The time  
spent waiting for the consumer to request the next data value would need to be factored into the  
calculation of total time.

## Question 2
The memory address register (MAR) and memory data register (MDR) are the interface between the internal CPU bus and the system bus. Why is the MAR write-only with respect to the CPU bus and read-only with respect to the system bus while the MDR can be both read and written from both buses?

The CPU can only act as a bus controller on the system bus; if it's participating in a data transaction, it is controlling the transaction. As such, the CPU will always be setting the address for any transaction it is involved in and the MAR can be uni-directional.

On the other hand, the system bus transactions controlled by the CPU could be reads or writes, meaning data many be transferred to or from the CPU respectively. As a result, the MDR must be fully bi-directional.

## Question 3
Reading from or writing to memory is much slower than a CPU internal bus cycle. Two approaches to solving this problem were discussed in the course notes: synchronously or asynchronously. What is one benefit and one drawback of each approach?

Synchronous:
- Consistent transaction time
- Must assume worst case transaction time every time

Asynchronous:
- No unnecessary waiting when a transaction finishes faster than worst case
- More control signals and logic necessary to manage transactions
