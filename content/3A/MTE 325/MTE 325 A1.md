1. What is hardware software co-design? What is the closest we have come to it so far?

Hardware software co-design is designing the hardware and software components of a system in parallel, instead of designing hardware first and then software after. The closest we are right now is FPGAs, where changes can be made to the hardware and recompiled before updating the corresponding software.

2. Define the terms.

- Microprocessor: Consists of a CPU only, no main memory or support for I/O devices. Performs all logic and arithmetic operations.
- Microcontroller: Includes a CPU as well as additional components, such as memory and I/O. it can be used as a stand-alone system.
- SoC: Fully functional computer system implemented in a computer chip. Different from a microcontroller because the configuration is chosen by the user.
- SoPC: SoC implemented with high-density, reconfigurable programmable logic devices. The user can reconfigure and program the chip logic.

3. Assume that an 8 bit interface register named `device_register` is mapped at location `0xC000`. Write the C source code to setup a pointer to the register, output a value from the register as a hexadecimal quantity, and then write a value of `0x0B` to the register.\\

```c
volatile unsigned char* device_register; // Declare pointer as voltatile
device_register = 0xC000; // Set pointer address
printf("Register Value = %X\n", *device_register); // Read register
*device_register = 0x0B; // Write a value of 0x0B to device
```

4. What are the 4 different methods of synchronization? Briefly describe the behavior of each.

- Blind cycle – No synchronization.
- Periodic polling – Poll status at set intervals.
- Occasional polling – Poll status when it is convenient to do so.
- Tight polling – Poll status constantly.
- Interrupts – Change in status generates an interrupt causing the system to poll and react to the status.

5. Which method of synchronization has the lowest latency from the perspective of a single device?

A tight polling loop results in the lowest latency from the perspective of a single device. The CPU dedicates 100% of its time towards servicing the device. As soon as the CPU observes a change in the status of the device, it will react.

6. When is it appropriate for interrupt synchronization to be used?

The CPU must have other tasks to complete for it to be worthwhile to use interrupts. If the CPU does not have other tasks, we are just adding increased complexity and latency without any tangible benefits.
